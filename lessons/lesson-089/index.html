🚀课程导读

代码报错或逻辑不对时，除了 Debug.Log，还有更专业的调试手段。本课教你“用编辑器抓 bug”。

◆断点调试（Visual Studio）

让程序“停在你指定的行”。

  1. 在 Visual Studio 打开脚本，在要检查的代码行左侧灰色区域【点击】打一个红色圆点（断点）。
  2. 点编辑器播放，再点 VS 顶部的【附加到 Unity Attach to Unity】（或直接按 F5）。
  3. 程序运行到断点处会【暂停】，VS 高亮当前行。
  4. 此时可【悬停变量】查看其当前值；用【即时窗口】输入表达式查看。
  5. 按【F10】逐语句执行、【F11】进入方法、【Shift+F11】跳出。
  6. 查看【监视窗口】添加要跟踪的变量。
  7. 排查完毕【移除断点】（点红点），点【继续 Continue】（F5）恢复运行。
  8. 【注意】断点会大幅降低运行速度，排查完务必移除。
💡
断点调试能看到“这一刻到底发生了什么”，比 Log 更精确。

◆Unity 内置调试技巧

不开 IDE 也能查。

  1. 【Inspector 实时观察】播放中选中对象，Inspector 里的字段实时变化，直接看到数值怎么变。
  2. 【折叠面板折叠调试】播放中可修改 Inspector 数值（停止会还原），用于“试参数”。
  3. 【暂停 + 逐帧】播放中点【⏸ 暂停】，再用【Step】逐帧前进，看对象每一帧的位置/状态。
  4. 【Game 视图 Stats】Game 视图右上角下拉选【Stats】，显示帧率、Draw Call、三角形数（性能相关）。
  5. 【场景视图运行中编辑】运行时在场景里拖动对象，观察实时效果（停止还原）。
  6. 【Console 过滤与折叠】用 Collapse、按级别过滤错误。
  7. 【Profiler】Window→Analysis→Profiler 看性能瓶颈（第 262 课）。
  8. 【Log 定位】Console 双击日志跳到代码行。
✅
调试套路：先看 Console 有没有红叉 → 断点看值 → Inspector 看状态 → 逐帧看过程。

⚠常见错误与排查

⛔
错误：断点不生效？
原因：VS 未附加到 Unity 或编译后没刷新
解决：确认 VS 点过“附加到 Unity”；脚本改动后 Unity 重编译需重新附加。

★动手练习

课后小任务（做出来才算真的学会）

  • 在某行打断点，附加 Unity 后运行并观察变量
  • 播放中用 Inspector 观察一个字段实时变化
  • 用暂停+逐帧看一个运动物体的位置变化
