🚀课程导读

Debug.Log 是你排查问题的最强武器。本课把它用到极致。

◆Debug 系列方法

三种级别 + 高级用法。

  1. 【Debug.Log(内容)】：输出普通信息（白色图标）。适合确认“代码执行到这里了”、“这个值是多少”。
  2. 【Debug.LogWarning(内容)】：输出警告（黄色图标），适合提示“值可能异常但还能跑”。
  3. 【Debug.LogError(内容)】：输出错误（红色图标），适合“这里不该发生”的严重问题。
  4. 内容可以是：数字、字符串、变量、对象：Debug.Log(playerName); Debug.Log(gameObject);
  5. 【多个参数】Debug.Log("名字：", player);
  6. 【条件输出】Debug.Log(条件表达式)，始终输出；想要“满足条件才输出”可用 if 包一层。
  7. 【带颜色的富文本】Debug.Log("<color=red>危险！</color>"); 文字变红（部分平台支持）。
💡
三种级别在 Console 里颜色/图标不同，一眼分辨问题严重性。

◆调试实战技巧

高效排查问题的套路。

  1. 【定位问题】在关键节点打点：方法开头打印"进入 TakeDamage"、结尾打印"伤害结算"，确认流程是否走通。
  2. 【输出变量值】计算前后各打一行，对比中间变化：Debug.Log($"之前:{hp} 之后:{hp - dmg}");
  3. 【输出对象引用】Debug.Log(target, target); 第二个参数传对象，点击日志可在 Hierarchy 高亮该对象。
  4. 【帧调试】在 Update 里打印位置：Debug.Log(transform.position); 观察每帧数值。
  5. 【画线调试】（进阶）Debug.DrawLine/ DrawRay 在场景里画线，直观看到方向与碰撞。
  6. 【条件断点】Console 顶部“Collapse”与暂停功能配合使用。
  7. 【清理】调试完记得删除多余的 Log，避免发布后刷屏与性能损耗。
✅
Debug 心法：先确认“有没有到这”→ 再确认“值对不对”→ 最后确认“为什么变这样”。

⚠常见错误与排查

⛔
错误：发布后 Console 看不到日志？
原因：发布版默认不显示编辑器 Console
解决：发布版日志在系统日志文件；调试在编辑器里看即可。
