“做完游戏怎么给别人玩”——发布。本课建立发布流程总览。

◆发布流程总览

四步上线。

  1. 【流程】
  2. 1. 准备（Player Settings、图标、场景）。
  3. 2. 选平台（Windows/WebGL/Android/iOS）。
  4. 3. Build（生成安装包）。
  5. 4. 测试发布（真机验证 + 上架/分发）。
  6. 【平台】
  7. Windows：exe 文件夹（PC 玩家）。
  8. WebGL：网页（浏览器即玩）。
  9. Android：APK/AAB（手机）。
  10. iOS：Xcode 工程（苹果 App Store）。
  11. 【Build Settings】File → Build Settings：
  12. Scenes In Build（场景列表）。
  13. Platform 选择（切换平台）。
  14. Build / Build And Run。
  15. 【切换平台】首次切换要等“导入平台模块”（Hub 安装）。
  16. 【产物】构建输出文件夹（可拷贝分享）。
  17. 【注意】平台切换有编译时间，提前规划。
  18. 【完成】流程“清楚”了！
💡
发布四步：准备 → 选平台 → Build → 测试分发。一步步来。

◆Build 前准备

别“裸奔”上线。

  1. 【Player Settings】Edit → Project Settings → Player：
  2. Company Name（公司）、Product Name（游戏名）。
  3. Default Icon（图标）、Cursor。
  4. 【公司/产品名】影响保存路径与显示名。
  5. 【场景检查】确认所有场景在 Scenes In Build（第 277 课）。
  6. 【清除日志】发布前清 Debug.Log（或用宏）。
  7. 【Version 版本号】设置版本（1.0.0）。
  8. 【Bundle Identifier】（移动端）唯一标识。
  9. 【基础】先做 Windows 版验证整体流程。
  10. 【完成后】再逐平台发布（第 282-285 课）。
  11. 【注意】命名/图标发布前定好，后改麻烦。
  12. 【完成】“准备就绪”。
  13. 【检查】Console 零报错是发布底线。
✅
发布准备三件：公司/产品名、图标、场景列表。三样就绪再 Build。

⚠常见错误与排查

⛔
错误：Build 报错？
原因：脚本错误/资源问题/平台未装
解决：先修 Console 报错；确认平台模块安装；看 Build 日志定位。
