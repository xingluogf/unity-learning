🚀课程导读

写代码必会遇到报错。Console 是你的“体检报告”，学会读它，你就打败了一半的恐惧。

◆认识 Console

打开控制台。

  1. 点击编辑器底部【Console】标签打开控制台窗口。
  2. 控制台里会不断刷新信息，常见有三种颜色/图标：
  3. 【信息 Info】(白色/蓝色图标)：正常运行日志，如 Debug.Log 输出的内容，无害。
  4. 【警告 Warning】(黄色三角)：有潜在问题但能运行，例如未赋值的引用、过时 API，应重视。
  5. 【错误 Error】(红色叉)：程序出错，通常导致功能失效或崩溃，必须修复。
  6. 每条日志都显示：内容、所在脚本和行号（如 Assets/Scripts/Test.cs:12）、点击可展开详细信息。
  7. 【双击一条错误】会打开对应脚本并跳转到出错的代码行，这是定位问题的黄金操作。
  8. 顶部按钮：【清除 Clear】清空日志、【折叠 Collapse】把重复日志合并、【暂停 Pause on Error】出现错误时自动暂停运行。
💡
报错不可怕，可怕的是一堆重复刷屏。用【折叠】按钮能让刷屏日志合并成一行，方便看真正的错误。

◆看懂一条典型报错

以最常见的“空引用”为例。

  1. 典型报错：NullReferenceException: Object reference not set to an instance of an object。
  2. 翻译：某个变量是“空的”(null)，但你却去用了它。比如你声明了一个 GameObject 变量却忘了赋值，然后在代码里访问它。
  3. 双击报错跳到代码行，检查：这一行用到的对象/组件是否已赋值？
  4. 常见修法：在 Start 里用 GetComponent 获取、或在 Inspector 手动拖入对象、或加判空 if (xxx != null)。
  5. 另一类高频：CS 编译错误（红色且带“CS”编号），如 CS1002（缺分号）、CS1039 等，按提示行号修即可。
  6. 养成习惯：每次运行前看 Console，有红叉先修再跑。
⚠️
警告(黄色)也别无视，很多警告是将来报错的前兆，尽量消灭在摇篮里。

⚠常见错误与排查

⛔
错误：控制台刷屏刷到看不见有用信息？
原因：循环里大量输出日志
解决：点【折叠】合并；排查代码中 Update 等高频函数里的 Debug.Log，减少无意义输出。

★动手练习

课后小任务（做出来才算真的学会）

  • 在脚本里故意写一行 Debug.Log(“hello”)，运行并查看 Console
  • 故意访问一个空对象，观察报错并双击定位到代码行
