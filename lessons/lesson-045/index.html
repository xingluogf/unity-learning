◆命名规范

统一规则，一眼看懂。

  1. 【文件/资源名】：全英文小写 + 下划线或驼峰，如 enemy_model、PlayerController.cs。
  2. 【脚本类名】：大驼峰（PascalCase），与文件名一致，如 PlayerController（文件名 PlayerController.cs）。
  3. 【变量名】：小驼峰（camelCase），如 playerSpeed、scoreValue。
  4. 【方法名】：大驼峰，如 StartMove()、TakeDamage()。
  5. 【常量】：全大写 + 下划线，如 MAX_HEALTH。
  6. 【禁止】：不能用中文命名文件/类/变量；不能以数字开头；不能与 Unity 关键字同名（如 transform、gameObject 大小写敏感）。
  7. 【前缀习惯】：UI 物体加 UI_ 前缀（UI_HealthBar），脚本功能清晰。
  8. 【Tag 与 Layer】：英文小写，如 Enemy、Player。
⛔
中文命名脚本是新手重灾区，会导致编译错误。全部使用英文命名！

◆目录组织规范

文件夹结构参考。

  1. Assets 下按类型分：Scenes / Scripts / Materials / Textures / Models / Audio / Prefabs / UI / Animations。
  2. 脚本再细分：Scripts/Player、Scripts/Enemy、Scripts/Managers、Scripts/UI。
  3. 预制体按用途：Prefabs/Characters、Prefabs/Props、Prefabs/UI。
  4. 场景文件放 Scenes，按关卡命名 level_01。
  5. 【文件夹不要乱套】：资源放对文件夹，找起来快，导入导出也好管理。
  6. 【版本管理意识】：配合 Git 时 Assets 全提交、Library/Temp 忽略（第 278 课）。
  7. 【存档规范】：项目文件多时定期备份，养成 Ctrl+S 习惯。
💡
规范不是束缚，是让你三个月后还能看懂自己的项目。

⚠常见错误与排查

⛔
错误：脚本保存后报错：文件名与类名不一致？
原因：文件名和类名必须一致
解决：把 .cs 文件名改为与类同名，或把类名改为与文件名相同。
